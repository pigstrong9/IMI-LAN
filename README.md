# IMI-LAN · 米家摄像头局域网直连

一个替代「IMI Camera」的轻量客户端。它不通过小米的公网 P2P 中转看视频，而是直接连接局域网里的摄像头，延迟和卡顿会明显低于原版客户端。

## 为什么原版会卡

原版 `IMI Camera.exe` 使用小米/TUTK 的 P2P SDK（`IOTCAPIs.dll`、`AVAPIs.dll`、`RDTAPIs.dll`），即使在同一个局域网里，也经常走公网中转节点（relay）。日志里可以看到大量 `rdt send start/finish`，视频链路并没有优先走局域网。

本项目使用开源的 [go2rtc](https://github.com/AlexxIT/go2rtc) 作为流媒体引擎。它实现了小米摄像头的 `miss` / `CS2` / `TUTK` 协议：

- 每次建立新连接时，向小米云端获取一次摄像头的本地加密密钥；
- 音视频数据只在本机与摄像头之间通过局域网传输；
- 浏览器通过 WebRTC / MSE 播放，延迟通常在 0.3–2 秒。

## 从仓库克隆后准备

仓库不含登录令牌、摄像头地址和引擎二进制（都在 `.gitignore` 里），第一次克隆后需要补齐三样东西：

1. 配置：复制 `go2rtc.yaml.example` 为 `go2rtc.yaml`。
2. 引擎：从 [go2rtc releases](https://github.com/AlexxIT/go2rtc/releases) 下载 Windows 版，改名成 `go2rtc.exe` 放到项目根目录。
3. 转码兜底：把 ffmpeg 的 Windows 构建放进 `bin/`，文件名保持 `ffmpeg.exe`（配置里 `ffmpeg.bin` 指向它）。自己用哪个构建都行；**如果打算把目录发给别人，选 LGPL 构建**，GPL 构建会带上提供源码的义务。

之后扫码登录，令牌和摄像头地址会自动写进 `go2rtc.yaml`。

## 第一次使用

1. 双击 `启动监控.bat`。
2. 会打开一个独立窗口（Chrome/Edge 的应用模式）。
3. 已经配置过摄像头的机器打开后会自动开始连接；新克隆的话先按上一节扫码登录，再点「添加摄像头」导入设备。

以后每次只需双击 `启动监控.bat`。

如果以后需要重新读取设备（换了摄像头、IP 变了）：

1. 点击「添加摄像头」。
2. 正常情况下会直接列出米家设备；如果要求登录，默认用「二维码登录」，也可以切到「账号密码」。
3. 勾选摄像头，点「添加选中摄像头」。

## 登录小米账号

- 推荐扫码：点「添加摄像头」→「二维码登录」→ 手机米家 App 右上角「＋」→「扫一扫」→ 确认。
- 扫码成功后，本地助手会把登录令牌写入 `go2rtc.yaml`，然后自动重启引擎（视频断开约 1–2 秒，属于正常现象）。
- 二维码助手 `qr-login.js` 用 Node 编写，随桌面版或 `启动监控.bat` 启动，只监听 `127.0.0.1:1985`，不再需要安装 Python。

> 如果密码登录提示 `xiaomi: 404 Not found` 一类的错误，通常是小米账号开启了两步验证。可以：
> - 在米家 App 里临时关闭「两步验证」，登录成功后再打开；
> - 或者继续使用当前已经导入的登录令牌（本机已完成，一般不用再登录）。

## 桌面版（Electron）

已打包的便携版：`desktop/dist/IMI-LAN-win32-x64/IMI-LAN.exe`，桌面快捷方式「米家监控」，也可以双击 `启动桌面版.bat`。

- 独立窗口、托盘、单实例；关闭窗口会隐藏到托盘，托盘右键菜单退出
- 自动启动并看护 go2rtc；自己启动的引擎异常退出会自动拉起
- 复用现有 `go2rtc.yaml` / `web`；二维码助手使用 Electron 自带 Node，无需 Python
- 记住窗口位置、大小、最大化和全屏状态；托盘菜单可开关「开机自启」
- 已验证 Electron 45 下 H.265 WebRTC 正常（2560×1440 等）

首次使用（让桌面版自己管理引擎）：

1. 运行 `修复网络权限（桌面版）.bat`（会弹 UAC；只给桌面版目录里的 `go2rtc.exe` 加入站规则，不影响原来的规则）
2. 如果旧版（Edge / `启动监控.bat`）的引擎或二维码助手还在运行，先运行 `停止监控.bat`，避免两边抢 1984/1985
3. 双击桌面「米家监控」；之后可以在托盘菜单「重启引擎」

如果启动时检测到 1984 已有引擎，桌面版会直接复用，不会再启动第二个；这时不需要做第 1 步。

说明：

- 便携版目录里有一份 `go2rtc.yaml`（含 token）和 `web`，和项目根目录是两份，互不影响；不要把便携版目录发给别人。
- exe 未签名，Windows SmartScreen 可能提示，选「更多信息 → 仍要运行」。
- 源码在 `desktop/`，`node_modules` 是构建依赖（约 250MB）；重新打包用 `desktop/package.json` 的 `pack:portable`，打包后需要把 `go2rtc.exe`、`go2rtc.yaml`、`web`、`bin`、`qr-login.js` 和两个防火墙 bat 复制进 `desktop/dist/IMI-LAN-win32-x64/`。

## 功能

- 多路摄像头网格，自动播放
- 双击画面（或点 ⛶）全屏查看；单击不会误开
- 全屏快捷键：← / → 切换上一路/下一路，空格静音，F 全屏，Esc 退出
- 每路可单独「暂停加载」：暂停后断开该路且不会自动重连，刷新页面仍保持暂停
- 连接失败自动重连，间隔 5s → 10s → 20s → 30s 递增，并显示当前是第几次
- 静音 / 取消静音
- 截图（JPG）
- 录制（WebM，浏览器本地编码）
- 画中画
- 画质切换（高清 / 流畅，按摄像头型号映射 `subtype`）
- 单路删除、一键清空、重新导入摄像头
- 连接失败时显示具体原因，可在卡片上直接重试
- 首页布局可调：1×1 / 2×2（默认，4 路）/ 3×2 / 3×3 / 全部
- 1×1 时顶栏出现切换器：下拉选摄像头，或用 ‹ › / ← → 切换
- 顶栏 ⛶ 全屏拼接：按当前布局把画面铺满整屏（1×1 一路、2×2 四路、3×2 六路…），无边框、无间隙、无按钮；Esc 或双击退出
- 画面比例可调：固定 16:9（不裁切）或铺满窗口（可能裁切）
- 默认隐藏门铃、喂食器等电池设备（可在设置里关闭）
- 默认「后台保持连接」并开启「后台 2 分钟后休眠」：切后台 2 分钟内不断流，超过 2 分钟释放解码内存，回来自动重连；关闭「保持」则切后台立即断开
- 每张卡片有 5 格信号条（1 格红 / 2-3 格黄 / 4-5 格绿），鼠标悬停显示当前下载速率（Mbps）
- 二维码登录（米家 App 扫码，不需要输入账号密码）
- 桌面版记住窗口位置/大小/全屏，托盘可开关开机自启

## 安全与隐私

- 网页和 API 只监听 `127.0.0.1:1984`，局域网内其他设备无法访问。
- 小米账号密码只在登录时提交给本机的 go2rtc，不会保存；保存的是登录令牌（在 `go2rtc.yaml` 里）。
- 摄像头密钥每次连接时向小米云端获取；音视频本身不经过公网。
- 二维码登录助手 `qr-login.js` 只监听 `127.0.0.1:1985`，只响应来自 `127.0.0.1:1984` / `localhost:1984` 的请求；不会把 token 返回给网页，只写入 `go2rtc.yaml`，日志里只记录脱敏账号。
- 不要把 `go2rtc.yaml` 发给别人，里面有账号令牌。
- `go2rtc.yaml`、`go2rtc.yaml.bak`、`*.log` 和 `desktop/dist/` 都已在 `.gitignore` 里；提交前用 `git status` 再确认一遍没有把它们带进去。
- 日志会记录配置文件的绝对路径（含 Windows 用户名）以及摄像头 IP 和设备 ID，往 issue 里贴日志前先删掉这几项。
- 令牌泄露后：改小米账号密码或在米家 App 里下线其他设备，旧 passToken 会失效，之后重新扫码登录即可。

## 常见问题

**画面黑屏 / 一直显示“连接中”或“连接超时”**

- 卡片遮罩上会显示具体原因（如 `i/o timeout`、`probe: no video`），点遮罩上的「重试」即可重连。
- 某台摄像头一直超时，先在电脑上 `ping` 它的 IP；ping 不通说明设备离线、休眠或 IP 变了，先查供电和 Wi-Fi，和网页无关。
- 同时拨号的路数越多越容易抖动，首页布局保持默认 2×2 会比 5 路全开更稳。
- 先退出原版 `IMI Camera`。它和本工具可能同时占用同一台摄像头，尤其是老型号。
- 确认摄像头在米家 App 里在线，且电脑和摄像头在同一个局域网/网段。
- 摄像头 IP 可能变了：点「设置 → 重新导入摄像头」，重新读取设备。
- 有些摄像头休眠后需要几秒唤醒，等 10–30 秒；门铃等电池设备首次连接会更慢。
- 如果 Windows 弹出防火墙提示，请允许 `go2rtc.exe` 访问「专用网络」；如果从没弹过提示，右键 `修复网络权限.bat` → 以管理员身份运行。
- 使用 Mesh 路由器（如 TP-Link Deco）时，个别摄像头会被“Mesh Technology / 客户端漫游”代理，导致局域网 UDP 握手失败；可在路由器里对该摄像头关闭该选项后重启摄像头。
- 需要看引擎细节时打开 http://127.0.0.1:1984/api/log 。

**提示“引擎未启动”**

双击 `启动监控.bat`，或检查 1984 端口是否被占用。

**二维码登录提示“服务未启动”**

- 桌面版：退出后重新打开即可（助手会使用 Electron 自带 Node 启动，端口 1985）；
- 网页版：`启动监控.bat` 会优先用桌面版自带的 Node 启动助手；如果两者都没有，请安装 Node.js，或直接用「账号密码」登录；
- 也可以手动运行：`node qr-login.js`（在项目目录下）。

**扫码后视频断开了一下**

正常现象：扫码成功后需要把新 token 写入配置并重启 go2rtc，视频会断 1–2 秒，之后自动重连。

**二维码过期了**

点二维码下方的「刷新二维码」重新生成一张。

**想彻底删除登录信息**

关闭浏览器和 go2rtc 后，删除 `go2rtc.yaml` 里的 `xiaomi:` 段，或直接删除整个 `imi-lan` 文件夹。

**延迟还是高**

- 确认电脑和摄像头在同一个 Wi-Fi/局域网（不要在访客网络或跨网段）；
- 在画质菜单切到「流畅」；
- 关闭其他正在占用摄像头的东西（米家 App、原版 IMI Camera）。

## 说明

- 本项目不修改摄像头固件，也不影响米家 App 的正常使用。
- 视频解码由浏览器完成；H.265 需要系统/浏览器支持硬件解码。
- 卡片右下角会显示当前播放方式：`RTC`（WebRTC，延迟最低）或 `MSE`（兼容性兜底）。WebRTC 协商失败时会自动退回 MSE。
- 首页布局、画面比例、门铃过滤保存在浏览器 localStorage（`imi.settings`），手动暂停的摄像头保存在 `imi.paused`；换浏览器或清缓存后会恢复默认「2×2 + 16:9 + 隐藏门铃」。
- 打开「添加摄像头」读取设备列表时，会自动把米家 App 里的昵称补到已添加的卡片上；换浏览器/清缓存后也能恢复中文名。
- 高清/流畅不是固定编号：不同型号的 `subtype` 不同，已在 `web/app.js` 的 `QUALITY_BY_MODEL` 里按型号映射；新增型号时先试 `subtype=2/3`。
- `bin/ffmpeg.exe` 只在 H.265 转码时用到，自己备份项目时别丢掉；但它是 GPL 构建，**不要把它放进发给别人的便携版目录**。
- 改完 `web/` 下的文件后，把 `index.html` 里 `?v=` 的日期改一下（或按 Ctrl+Shift+R），否则浏览器可能继续使用旧缓存。
- PTZ（云台控制）暂未实现，目前可以在米家 App 里控制。
